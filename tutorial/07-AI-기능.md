# 07. AI 기능 붙이기

목표: AI가 **지어내지 않게** 만드는 법. 모델을 부르는 것 자체는 쉽고, 어려운
건 답변을 신뢰할 수 있게 만드는 구조다.

---

## 1. 설정

```jsonc
// wrangler.jsonc
"ai": { "binding": "AI" }
```

이것만으로 `env.AI`를 쓸 수 있다. 모델을 따로 설치하거나 API 키를 받을 필요가 없다.

```js
const result = await env.AI.run("@cf/qwen/qwen3-30b-a3b-fp8", {
  messages: [
    { role: "system", content: "너는 도움을 주는 조수다." },
    { role: "user",   content: "안녕" },
  ],
});
return Response.json({ answer: result.response });
```

> **주의**: Workers AI는 **로컬 개발에서도 실제 계정에 과금된다**(무료 할당량을
> 넘으면). `wrangler dev`로 테스트할 때도 실제 호출이 나간다.

## 2. 문제: 그냥 물어보면 지어낸다

모델은 모르는 것도 **그럴듯하게** 답한다. 규정·안전 정보처럼 정확성이 중요한
내용에서는 이게 치명적이다.

## 3. 해결: 근거를 먼저 찾아 넘긴다 (RAG)

```
사용자 질문
   │
   ├─ 1. 내 데이터베이스에서 관련 문서를 검색
   │
   ├─ 2. 못 찾으면 → 모델을 아예 부르지 않는다
   │                  ("관련 자료를 찾지 못했습니다")
   │
   └─ 3. 찾으면 → 그 발췌만 프롬프트에 넣고
                  "문서에 없는 내용은 지어내지 말라"고 지시
```

**핵심은 2번이다.** 근거가 없으면 부르지 않는다. 비용도 아끼고, 근거 없는
답변도 막는다.

```js
async function handleChat(request, env){
  const { messages } = await request.json();
  const question = messages[messages.length - 1].content;

  const docs = await searchDocs(env, question);        // 1
  if (docs.length === 0){                               // 2
    return Response.json({
      ready: true,
      answer: "관련 자료를 찾지 못했습니다. 공식 정보를 확인해주세요.",
      sources: [],
    });
  }

  const context = docs.map(d => `[${d.title}]\n${d.body}`).join("\n\n");
  const result = await env.AI.run(MODEL, {                // 3
    messages: [
      { role: "system", content:
        "아래 참고 문서만 근거로 답하라. 문서에 없는 내용은 지어내지 말고 " +
        "모른다고 답하라. 답변 끝에 참고 정보임을 덧붙여라.\n\n" + context },
      ...messages,
    ],
  });

  return Response.json({
    ready: true,
    answer: result.response,
    sources: docs.map(d => ({ title: d.title, sourceUrl: d.sourceUrl })),
  });
}
```

**출처를 같이 돌려준다.** 사용자가 원문을 확인할 수 있어야 신뢰가 생긴다.

## 4. 검색: D1 전문검색(FTS5)

문서가 수십 개 규모면 벡터 임베딩까지 갈 필요가 없다. D1이 SQLite의 전문검색을
지원한다.

```sql
-- 본문은 원래 표에 두고, FTS5 는 색인만 갖는다 (external content 방식)
CREATE VIRTUAL TABLE IF NOT EXISTS docs_fts USING fts5(
  title, body,
  content='docs', content_rowid='id',
  tokenize='trigram'
);

-- 원본이 바뀌면 색인도 따라 바뀌게 트리거를 걸어둔다
CREATE TRIGGER IF NOT EXISTS docs_ai AFTER INSERT ON docs BEGIN
  INSERT INTO docs_fts(rowid, title, body) VALUES (new.id, new.title, new.body);
END;
```

```js
const { results } = await env.DB
  .prepare("SELECT d.* FROM docs_fts f JOIN docs d ON d.id = f.rowid " +
           "WHERE docs_fts MATCH ?1 LIMIT 5")
  .bind(term).all();
```

### 한국어에서 겪은 문제 두 가지

**1) 2글자 단어가 검색되지 않는다.**
`tokenize='trigram'`은 연속 3글자를 색인 단위로 쓴다. "신고", "번호"처럼 2글자
단어는 그 최소 조건을 못 채워서 아예 안 걸린다.

→ 3글자 이상은 FTS5로, 2글자는 `LIKE '%단어%'` 전체 스캔으로 따로 찾아 합쳤다.
문서가 수십 개면 스캔 비용이 무시할 만하다. 수백 개로 늘면 이 절충은 다시 봐야 한다.

**2) 조사가 붙으면 매칭이 깨진다.**
"풍랑주의보에는"처럼 조사가 붙으면 문서의 "풍랑주의보"와 문자열이 달라진다.

→ 형태소 분석기 없이 흔한 조사만 잘라내는 얕은 처리로 재현율을 올렸다.
완벽하지 않지만 이 규모에서는 실용적이다.

**교훈**: 한국어 검색은 영어보다 손이 더 간다. 완벽을 노리지 말고 **규모에 맞는
절충**을 하고, 그 절충이 왜 괜찮은지(그리고 언제 다시 봐야 하는지) 주석에 남긴다.

## 5. AI 답변도 신뢰할 수 없는 입력이다

모델이 만든 문자열을 화면에 그대로 넣으면 안 된다.

```js
// ✅ 반드시 이스케이프
chatAppend(chatBubble("bot", esc(j.answer)));
```

**왜**: 사용자가 질문에 HTML을 넣고 "이걸 그대로 반복해줘"라고 하면, 모델이
그 HTML을 답변에 옮겨 적을 수 있다(프롬프트 인젝션). 그게 `innerHTML`로 들어가면
실행된다. 답변 출처가 내 모델이든 남의 입력이든, **화면에 넣기 전엔 이스케이프**다.

## 6. 계산은 한 곳에만

이 저장소는 점수 계산을 **프론트엔드에만** 두고, 챗봇에 넘길 때 클라이언트가
계산한 값을 함께 보낸다.

```js
// 클라이언트가 점수를 계산해서 같이 보낸다
body: JSON.stringify({ messages, spots: 계산된점수목록 })
```

**왜 서버에서 다시 계산하지 않나**: 계산 로직이 두 벌이 되면 반드시 어긋난다.
지도에 82점으로 뜨는 곳을 챗봇이 다르게 말하는 사고가 난다. 사용자가 값을
조작해 보내도 자기 대화에만 영향이 있으니 감수할 수 있는 위험이었다.

**일반 규칙**: 같은 계산을 두 곳에 두지 않는다. 어느 쪽에 둘지는 "그 값을
화면에 보여주는 쪽"을 기준으로 정하면 대개 맞다.

## 7. 비용 관리

```js
// 대화 이력은 최근 8왕복까지만, 한 메시지는 500자까지만 넘긴다
messages: chatState.history.slice(-8)
```

```html
<input id="chat-input" type="text" maxlength="500">
```

토큰이 곧 비용이다. 이력을 무한히 넘기면 대화가 길어질수록 비싸진다.
레이트 리밋도 같이 건다(→ [05번 문서](./05-데이터-저장하기-D1.md#5-도배-방지-레이트-리밋)).

## 8. 자원이 없을 때

```js
if (!env.AI || !env.DB){
  return Response.json({ ready: false, reason: "not_configured" });
}
```

화면은 "도우미가 아직 준비되지 않았습니다"로 표시한다. **부가 기능이 죽어도
주요 화면은 떠야 한다**는 원칙을 여기서도 지킨다.

---

## 자주 겪는 문제

**`env.AI` 가 `undefined`**
`wrangler.jsonc`에 `"ai": { "binding": "AI" }`가 있는지 확인하고 dev 서버를
재시작한다.

**답변이 계속 엉뚱하다**
프롬프트보다 **검색 결과**를 먼저 의심한다. 어떤 문서가 넘어갔는지 로그로
찍어본다. 근거가 엉뚱하면 답변도 엉뚱하다.

**한국어 검색이 아무것도 못 찾는다**
2글자 단어와 조사 문제(4번 항목)를 확인한다. 먼저 `LIKE '%단어%'`로 직접
조회해서 문서 자체에 그 단어가 있는지 본다.

**응답이 너무 느리다**
모델 호출은 수 초가 걸린다. 화면에 "입력 중" 표시를 넣고, 버튼을 비활성화해
중복 요청을 막는다.
