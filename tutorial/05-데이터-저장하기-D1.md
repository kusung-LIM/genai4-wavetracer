# 05. 데이터 저장하기 (D1)

목표: SQL 데이터베이스를 붙이고, **사용자 입력을 안전하게** 받는 법.

사용자 입력을 받는 순간 고려할 게 세 가지 늘어난다. 그게 이 문서의 절반이다.

---

## 1. D1 만들고 연결하기

```bash
npx wrangler d1 create my-database
```

출력에 나온 설정을 `wrangler.jsonc`에 붙여넣는다.

```jsonc
"d1_databases": [
  { "binding": "DB", "database_name": "my-database", "database_id": "여기에-출력된-id" }
]
```

`binding: "DB"`는 "코드에서 `env.DB`로 부르겠다"는 뜻이다.

```bash
npx wrangler d1 list          # 내 데이터베이스 목록
npx wrangler d1 info my-database   # 크기·상태
```

## 2. 스키마 (표 구조 정의)

`schema.sql` 파일에 표 정의를 적어두고, 그 파일을 적용한다.

```sql
-- schema.sql
-- IF NOT EXISTS 로 적어두면 여러 번 적용해도 안전하다 (멱등)
CREATE TABLE IF NOT EXISTS reports (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  nickname   TEXT NOT NULL,
  body       TEXT NOT NULL,
  rating     INTEGER,
  created_at TEXT NOT NULL,
  ip_hash    TEXT
);
CREATE INDEX IF NOT EXISTS idx_reports_created ON reports(created_at DESC);
```

**`IF NOT EXISTS`를 꼭 붙인다.** 그러면 스키마 파일을 여러 번 적용해도 에러가
나지 않고, 새 표를 추가할 때 파일 하나만 다시 돌리면 된다.

**인덱스**는 자주 검색·정렬하는 열에 붙인다. 없으면 표 전체를 훑어야 한다.

### 로컬과 원격은 별개의 데이터베이스다

```bash
npx wrangler d1 execute my-database --local  --file=./schema.sql   # 내 PC용
npx wrangler d1 execute my-database --remote --file=./schema.sql   # 실제 배포용
```

**이걸 자주 잊는다.** 로컬에서 잘 되는데 배포 후 "no such table" 에러가 나면
`--remote`를 안 돌린 것이다.

### 직접 조회해 보기

```bash
npx wrangler d1 execute my-database --local --command "SELECT COUNT(*) FROM reports;"
npx wrangler d1 execute my-database --remote --command "SELECT * FROM reports LIMIT 5;"
```

## 3. 코드에서 읽고 쓰기

```js
// 읽기 — 여러 행
const { results } = await env.DB
  .prepare("SELECT * FROM reports ORDER BY created_at DESC LIMIT ?1")
  .bind(30)
  .all();

// 읽기 — 한 행
const row = await env.DB
  .prepare("SELECT * FROM reports WHERE id = ?1")
  .bind(id)
  .first();

// 쓰기
await env.DB
  .prepare("INSERT INTO reports (nickname, body, created_at) VALUES (?1, ?2, ?3)")
  .bind(nickname, body, new Date().toISOString())
  .run();
```

### `?1`을 반드시 쓴다 (SQL 인젝션 방어)

```js
// ❌ 절대 하지 말 것 — 값을 문자열로 이어붙이기
`SELECT * FROM reports WHERE nickname = '${nickname}'`
```

`nickname`에 `' OR 1=1 --` 같은 값이 오면 조건이 무력화되고, 최악의 경우 표가
삭제된다. **`?1`, `?2`로 자리를 만들고 `.bind()`로 값을 넘기면** 값은 항상
값으로만 취급된다.

## 4. 사용자 입력 다루기 (XSS)

### 무엇이 문제인가

누군가 닉네임에 이렇게 쓴다.

```html
<img src=x onerror="alert('당했다')">
```

이걸 `innerHTML`에 그대로 넣으면 **그 코드가 실행된다.** 실제로는 알림창이
아니라 쿠키를 훔치거나 다른 사이트로 보내는 코드가 들어온다.

### 방어

```js
// public/js/util.js
const esc = s => String(s).replace(/[&<>"]/g,
  c => ({ "&":"&amp;", "<":"&lt;", ">":"&gt;", '"':"&quot;" }[c]));
```

`<`를 `&lt;`로 바꾸면 브라우저가 **태그가 아니라 글자로** 취급한다.

```js
// ✅ 화면에 넣기 직전에 통과시킨다
'<span>' + esc(r.nickname) + '</span>'
```

### 세 가지 규칙

**1) 저장은 원문, 이스케이프는 출력 시점에.**
저장할 때 변환해 두면 나중에 다른 곳(예: 이메일, 파일)에 쓸 때 이상해진다.

**2) 자르기 → 이스케이프 순서를 지킨다.**
```js
esc(excerpt(text, 100))    // ✅ 자른 뒤 이스케이프
excerpt(esc(text), 100)    // ❌ &amp; 같은 게 중간에 잘려 깨진다
```

**3) 에러 메시지는 `textContent`로.**
서버가 준 메시지를 `innerHTML`에 넣지 않는다.

### 확인 방법

닉네임에 `<img src=x onerror=alert(1)>`를 넣어 제출해 본다. **알림창이 뜨면
취약**하고, 글자로 그대로 보이면 안전하다. 사용자 입력을 받는 곳을 새로 만들
때마다 이 테스트를 한다.

## 5. 도배 방지 (레이트 리밋)

로그인이 없으면 누구나 무한히 쓸 수 있다. "같은 곳에서 온 요청 수"를 세서
제한한다.

```js
// src/worker.js 의 패턴
const RATE_LIMIT_MAX = 5;          // 10분에 5건
const RATE_LIMIT_WINDOW_MIN = 10;

const windowStart = new Date(Date.now() - RATE_LIMIT_WINDOW_MIN * 60000).toISOString();
const { results } = await env.DB
  .prepare("SELECT COUNT(*) AS n FROM reports WHERE ip_hash = ?1 AND created_at > ?2")
  .bind(ipHash, windowStart)
  .all();

if (results[0].n >= RATE_LIMIT_MAX){
  return Response.json({ message: "잠시 후 다시 시도해주세요." }, { status: 429 });
}
```

## 6. IP를 그대로 저장하지 않기

IP는 개인정보다. 그대로 쌓으면 관리 책임이 생긴다.
**해시만 저장하면** 같은 사람인지 구별하는 목적은 달성하면서 원본은 남지 않는다.

```js
// src/worker.js
const REPORT_SALT = "myapp-report-v1-salt";   // 앱마다 다른 고정 문자열

async function sha256Hex(text){
  const buf = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(text));
  return Array.from(new Uint8Array(buf)).map(b => b.toString(16).padStart(2, "0")).join("");
}

const ip = request.headers.get("CF-Connecting-IP") || "";
const ipHash = await sha256Hex(ip + REPORT_SALT);
```

`CF-Connecting-IP`는 Cloudflare가 넣어주는 실제 방문자 IP 헤더다.

**솔트(salt)를 붙이는 이유**: 해시만 저장해도 흔한 IP는 미리 계산해둔 표로
역추적할 수 있다. 앱마다 다른 문자열을 섞으면 그게 어려워진다. 완전한 익명화는
아니지만 원본 IP를 쌓아두는 것보다 낫다.

## 7. 입력 검증은 서버가 최종 판단

클라이언트 검증은 **왕복 없이 빨리 알려주기 위한 편의**다. 브라우저 코드는
누구나 고칠 수 있으니 서버가 다시 검사해야 한다.

```js
// src/worker.js — 서버 검증 (최종)
if (typeof nickname !== "string" || nickname.length < 1 || nickname.length > 20){
  return Response.json({ message: "닉네임은 1~20자로 입력해주세요." }, { status: 400 });
}
if (rating !== undefined && (!Number.isInteger(rating) || rating < 1 || rating > 5)){
  return Response.json({ message: "별점은 1~5 사이여야 합니다." }, { status: 400 });
}
```

이 저장소는 프론트에 **같은 규칙을 거울처럼** 한 벌 더 뒀다
(`public/js/reports.js`의 `validateReportClient`). 여기서 뚫려도 서버가 막으니
보안에는 영향이 없다.

## 8. 저장소가 죽어도 앱은 뜨게

```js
if (!env.DB){
  // 바인딩이 없으면 에러가 아니라 "준비 안 됨"
  return Response.json({ ready: false, reports: [] });
}
```

게시판은 부가 기능이다. 데이터베이스에 문제가 있어도 예보 화면은 떠야 한다.
화면에서도 빈 상태를 **에러가 아니라 안내로** 그린다("첫 제보를 남겨보세요").

## 9. 무료 한도를 생각한 설계

D1 무료 한도는 **하루 쓰기 10만 행**이다(읽기는 더 넉넉하다).

이 저장소가 실제로 부딪힌 계산:

```
13개 지점 × 7일 × 24시간 = 2,184행
15분마다 다시 쓰면 × 96회 = 하루 20만 행  ❌ 한도 초과
```

해결: **"지점 × 날짜"로 한 행만 두고 하루 24시간을 JSON 배열로 접어 넣었다.**

```
13개 지점 × 7일 = 91행 × 96회 = 하루 8,736행  ✅
```

```sql
CREATE TABLE IF NOT EXISTS spot_daily (
  spot_id TEXT NOT NULL,
  date    TEXT NOT NULL,
  hourly  TEXT NOT NULL,     -- [[시각, 값1, 값2, ...], ...] 를 JSON 문자열로
  PRIMARY KEY (spot_id, date)
);
```

배열에 키 이름을 반복하지 않고 **자리(위치)로** 값을 넣어 크기를 더 줄였다.

**단점**: 자리 순서가 곧 계약이 된다. 순서를 바꾸면 에러 없이 파고 자리에
주기가 들어가는 식으로 조용히 틀린다. 그래서 이 저장소는 그 순서를 테스트로
못박아 뒀다(`test/score.test.mjs`).

## 10. 직접 해보기

방명록을 만들어 보자.

**1) 스키마 추가** (`schema.sql`에 덧붙이고 로컬·원격 모두 적용)
```sql
CREATE TABLE IF NOT EXISTS guestbook (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL,
  message    TEXT NOT NULL,
  created_at TEXT NOT NULL
);
```

**2) 서버** (`src/worker.js`)
```js
if (url.pathname === "/api/guestbook"){
  if (request.method === "GET"){
    const { results } = await env.DB
      .prepare("SELECT * FROM guestbook ORDER BY id DESC LIMIT 20").all();
    return Response.json({ entries: results });
  }
  if (request.method === "POST"){
    const b = await request.json().catch(() => null);
    if (!b || typeof b.name !== "string" || b.name.length < 1 || b.name.length > 20){
      return Response.json({ message: "이름은 1~20자" }, { status: 400 });
    }
    if (typeof b.message !== "string" || b.message.length < 1 || b.message.length > 200){
      return Response.json({ message: "내용은 1~200자" }, { status: 400 });
    }
    await env.DB.prepare(
      "INSERT INTO guestbook (name, message, created_at) VALUES (?1, ?2, ?3)")
      .bind(b.name, b.message, new Date().toISOString()).run();
    return Response.json({ ok: true }, { status: 201 });
  }
  return new Response("Method Not Allowed", { status: 405 });
}
```

**3) 화면** — 목록을 그릴 때 `esc()`를 꼭 통과시킨다.
```js
const data = await fetch("/api/guestbook").then(r => r.json());
app.innerHTML = data.entries.map(e =>
  '<div class="card"><b>' + esc(e.name) + '</b><p>' + esc(e.message) + '</p></div>'
).join("");
```

**4) 확인** — 정상 입력 / 빈 입력(400) / `<img src=x onerror=alert(1)>` 입력
(글자로 보이면 안전) 세 가지를 테스트한다.

## 자주 겪는 문제

**`D1_ERROR: no such table`**
스키마를 적용하지 않았다. `--local`과 `--remote`를 **각각** 돌렸는지 확인한다.

**`env.DB` 가 `undefined`**
`wrangler.jsonc`의 `d1_databases` 선언을 확인하고 `wrangler dev`를 재시작한다.

**로컬 D1 명령이 멈춘 것처럼 안 끝난다**
`wrangler dev`가 켜져 있으면 같은 파일을 잡고 있어 충돌할 수 있다. dev 서버를
끄고 다시 시도한다.

**한글이 `????`로 저장된다**
요청·응답 헤더에 `charset=utf-8`이 있는지 확인한다.
`Response.json()`을 쓰면 자동으로 처리된다.

**날짜 정렬이 이상하다**
날짜를 `new Date().toISOString()` 형식(`2026-09-09T06:44:25.870Z`)으로 저장하면
문자열 정렬이 곧 시간 정렬이 된다. 형식을 섞지 않는다.
