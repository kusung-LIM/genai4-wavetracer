# 01. 기초 지식 — 딱 이만큼만

이 앱을 다루는 데 실제로 필요한 개념만 모았다. JavaScript 문법책을 다 볼 필요는
없다. 아래 것들만 감이 오면 이 저장소의 코드는 읽힌다.

---

## 1. 웹앱이 화면에 뜨는 과정

```
1. 브라우저가 주소로 요청  →  2. 서버가 index.html 을 준다
3. 브라우저가 HTML 을 읽다가 <link>·<script> 를 만나면 그 파일도 받아온다
4. JavaScript 가 실행되면서 화면을 그리거나 고친다
5. 필요하면 JavaScript 가 추가로 데이터를 요청한다 (fetch)
```

이 앱은 4번과 5번에서 대부분의 일이 일어난다. HTML(`public/index.html`)은
**빈 껍데기와 뼈대만** 들고 있고, 실제 내용은 JavaScript가 채운다.

`public/index.html`을 열어보면 `<div id="app"></div>`가 있다. 이 빈 칸에
JavaScript가 화면을 그려 넣는다.

## 2. HTML / CSS / JavaScript 의 역할

| | 무엇 | 이 저장소에서 |
|---|---|---|
| HTML | 구조 (무엇이 있나) | `public/index.html` |
| CSS | 모양 (어떻게 보이나) | `public/css/app.css` |
| JavaScript | 동작 (무엇을 하나) | `public/js/*.js` |

## 3. JavaScript — 이 코드를 읽는 데 필요한 것만

### 값과 함수

```js
const x = 3;            // 바뀌지 않는 값
let y = 3;              // 바뀔 수 있는 값
function f(a, b){ return a + b; }
const g = (a, b) => a + b;      // 위와 같은 뜻 (화살표 함수)
```

이 저장소는 `const`를 기본으로 쓰고, 바뀌어야 할 때만 `let`을 쓴다.

### 객체와 배열

```js
const spot = { id: "jukdo", name: "죽도 해변", lat: 38.0158 };
spot.name           // "죽도 해변"
spot["name"]        // 같은 것

const list = [1, 2, 3];
list.length         // 3
list[0]             // 1
```

### 배열을 다루는 세 가지 (이 코드에 계속 나온다)

```js
const nums = [1, 2, 3, 4];

nums.map(n => n * 2)          // [2, 4, 6, 8]      각각 바꿔서 새 배열
nums.filter(n => n > 2)       // [3, 4]            조건에 맞는 것만
nums.find(n => n > 2)         // 3                 조건에 맞는 첫 번째 하나
```

`map`은 화면을 그릴 때 계속 쓴다 — "13개 지점을 각각 HTML 조각으로 바꿔서 이어붙여라".

```js
// public/js/home.js 에서 실제로 이런 식으로 쓴다
const html = SPOTS.map(s => "<li>" + s.name + "</li>").join("");
```

### 값이 없을 때: null / undefined

```js
null          // "값이 없음"을 의도적으로 표시
undefined     // 아직 아무것도 안 넣음 / 없는 속성을 읽었을 때
```

**이 프로젝트에서 가장 중요한 개념 중 하나다.** 파고 데이터가 없는 시간대는
0이 아니라 `null`이다. 0으로 채우면 "파고 0m = 잔잔함"이라는 **틀린 정보**를
자신 있게 보여주게 된다.

그래서 코드에 이런 검사가 계속 나온다.

```js
const isNum = v => typeof v === "number" && Number.isFinite(v);
// 숫자인가? (null, undefined, NaN 을 전부 걸러낸다)

isNum(h.waveH) ? h.waveH.toFixed(1) + "m" : "–"    // 없으면 대시 표시
```

### 물음표 문법 세 가지

```js
a?.b            // a 가 null/undefined 면 에러 대신 undefined
a ?? b          // a 가 null/undefined 면 b 를 쓴다
a ? b : c       // a 가 참이면 b, 아니면 c
```

`?.`가 없으면 `a.b.c`에서 `a.b`가 없을 때 프로그램이 멈춘다. 외부에서 온
데이터를 다룰 때 특히 유용하다.

```js
// src/worker.js — 응답 구조가 예상과 다를 수 있으니 ?. 로 방어하고, 없으면 [] 로
const items = listData?.response?.body?.items?.item ?? [];
```

### 비동기: async / await

네트워크 요청은 시간이 걸린다. 결과를 기다려야 한다.

```js
async function load(){
  const res  = await fetch("/api/reports");   // 응답이 올 때까지 기다림
  const data = await res.json();              // 본문을 JSON 으로 해석
  return data;
}
```

- `await`는 `async` 함수 안에서만 쓸 수 있다.
- `await`를 빼먹으면 데이터 대신 "약속(Promise)" 객체가 들어와서 이상하게 동작한다.
  화면에 `[object Promise]`가 보이면 `await`를 빠뜨린 것이다.

여러 개를 **동시에** 기다릴 때:

```js
const [a, b] = await Promise.all([ loadA(), loadB() ]);   // 둘을 같이 시작
```

### 모듈: import / export

파일을 나눠 쓰는 방법이다. 이 저장소 프론트엔드가 이 구조다.

```js
// util.js
function esc(s){ /* ... */ }
export { esc };

// home.js
import { esc } from "./util.js";
```

규칙 두 개만 기억하면 된다.
- 경로에 **`.js` 확장자를 반드시** 쓴다 (`"./util.js"`, `"./util"`은 안 됨).
- HTML에서 `<script type="module">`로 불러야 `import`가 동작한다.

## 4. 브라우저가 주는 도구들

### DOM — 화면을 코드로 다루기

```js
document.querySelector("#app")       // id 가 app 인 요소 하나
document.querySelectorAll(".tab")    // class 가 tab 인 요소 전부

el.innerHTML = "<p>안녕</p>";        // 안쪽 HTML 을 통째로 교체
el.textContent = "안녕";             // 글자만 넣기 (HTML 로 해석 안 함)
el.addEventListener("click", () => { /* 눌렀을 때 */ });
```

이 저장소는 짧게 쓰려고 별칭을 만들어 뒀다.

```js
// public/js/util.js
const $  = (s, r) => (r || document).querySelector(s);
const $$ = (s, r) => Array.from((r || document).querySelectorAll(s));
```

**`innerHTML`과 `textContent`의 차이는 보안 문제다.** 남이 입력한 값을
`innerHTML`에 그대로 넣으면 그 안의 `<script>`가 실행된다.
→ [05번 문서의 XSS](./05-데이터-저장하기-D1.md#사용자-입력-다루기-xss)

### localStorage — 브라우저에 값 남기기

```js
localStorage.setItem("wt:level", "beginner");
localStorage.getItem("wt:level");        // "beginner"
```

- 그 브라우저에만 남는다. 다른 기기와 공유되지 않는다.
- 시크릿 모드 등에서 막혀 있을 수 있어서 이 저장소는 항상 `try`로 감싼다.

### fetch — 데이터 요청

```js
const res  = await fetch("/api/reports");
if (!res.ok) throw new Error("HTTP " + res.status);   // 200번대가 아니면 실패
const data = await res.json();
```

**`fetch`는 404나 500에도 예외를 던지지 않는다.** `res.ok`를 직접 확인해야 한다.
이걸 놓치면 에러 페이지 HTML을 JSON으로 해석하려다 이상한 에러가 난다.

## 5. Cloudflare 용어

| 용어 | 뜻 |
|---|---|
| **Worker** | 서버 코드. 요청이 올 때만 실행되고, 안 쓰면 비용이 없다. `src/worker.js` |
| **정적 에셋(Static Assets)** | HTML·CSS·이미지처럼 그대로 내려주는 파일. `public/` 폴더 |
| **D1** | Cloudflare가 주는 SQL 데이터베이스 (SQLite 호환) |
| **Workers AI** | 미리 올라가 있는 AI 모델을 부르는 기능 |
| **Cron Trigger** | 정해진 시각에 Worker를 자동 실행 |
| **바인딩(binding)** | Worker가 자원(DB·AI 등)에 접근하는 이름. `wrangler.jsonc`에 선언하면 코드에서 `env.DB`처럼 쓴다 |
| **시크릿(secret)** | 인증키처럼 코드에 넣으면 안 되는 값. 따로 등록한다 |
| **wrangler** | Cloudflare를 다루는 명령줄 도구 |

### 바인딩이 실제로 어떻게 이어지는가

```jsonc
// wrangler.jsonc — "DB 라는 이름으로 이 데이터베이스를 쓸게"
"d1_databases": [
  { "binding": "DB", "database_name": "wavetracer", "database_id": "..." }
]
```

```js
// src/worker.js — 그러면 코드에서 env.DB 로 쓸 수 있다
export default {
  async fetch(request, env, ctx){
    const rows = await env.DB.prepare("SELECT * FROM reports").all();
  }
};
```

`wrangler.jsonc`에 선언하지 않으면 `env.DB`는 `undefined`다. **"자원을 쓰려면
먼저 설정 파일에 선언한다"**가 Cloudflare의 기본 규칙이다.

## 6. 알아두면 좋은 나머지

**HTTP 상태 코드** — 200 성공 / 400 요청이 잘못됨 / 403 권한 없음 /
404 없음 / 429 너무 많이 요청함 / 500·502 서버 쪽 문제

**JSON** — 데이터를 주고받는 글자 형식.
`JSON.stringify(객체)`로 글자로, `JSON.parse(글자)`로 객체로 바꾼다.

**CORS** — 브라우저가 "다른 도메인에 요청해도 되나?"를 검사하는 규칙.
상대 서버가 허용해야 브라우저에서 직접 부를 수 있다.
→ [04번 문서](./04-외부-데이터-가져오기.md#cors란-무엇이고-왜-막히나)

**git** — 코드 변경 이력. 최소한 이 셋만:
```bash
git status              # 뭐가 바뀌었나
git diff                # 어떻게 바뀌었나
git restore <파일>      # 이 파일 변경을 버리고 되돌리기
```
