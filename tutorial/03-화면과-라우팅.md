# 03. 화면과 라우팅

목표: 화면이 여러 개인 앱을 **프레임워크 없이** 만드는 법.

---

## 1. 이 앱의 화면 구성 방식

HTML 파일은 **하나뿐이다**(`public/index.html`). 주소가 바뀌면 JavaScript가
`<div id="app">` 안쪽을 갈아끼운다. 이런 방식을 SPA(Single Page Application)라 한다.

```
/            → 홈 화면을 app 안에 그림
/forecast    → 예보 화면을 app 안에 그림
/reports     → 게시판 화면을 app 안에 그림
```

**왜 파일을 여러 개 두지 않나**: 헤더·탭·챗봇처럼 모든 화면에 공통인 부분이
파일마다 복제된다. 하나 고치려면 전부 고쳐야 한다.

**대신 감수하는 것**: 첫 로딩에 JavaScript가 실행돼야 내용이 보인다. 검색엔진
노출이 중요한 사이트라면 이 방식이 불리하다.

## 2. HTML은 뼈대만

`public/index.html`의 구조를 보면 이렇다.

```html
<body>
<div class="wrap">
  <header>...로고...</header>

  <nav class="tabs">
    <a href="/"          data-nav data-route="home">홈</a>
    <a href="/forecast"  data-nav data-route="forecast">파도예보</a>
    <a href="/reports"   data-nav data-route="reports">파도제보</a>
  </nav>

  <div id="app"></div>          ← 여기가 화면마다 바뀌는 부분

  <footer>...</footer>
</div>
</body>
```

`data-nav`, `data-route`처럼 `data-`로 시작하는 속성은 **HTML에 내가 원하는 표시를
붙여두는 방법**이다. JavaScript에서 `el.dataset.route`로 읽는다. 여기서는
"이 링크는 라우터가 처리해야 한다(`data-nav`)"는 표시로 쓴다.

## 3. 링크를 가로채기

`<a href="/forecast">`를 그냥 누르면 브라우저가 **페이지를 새로 받아온다**.
전체 새로고침이 일어나 느리고, 화면이 번쩍인다.

그래서 클릭을 가로채서 주소만 바꾸고 화면은 JavaScript로 그린다.

```js
// public/js/router.js
document.addEventListener("click", e => {
  const a = e.target.closest("a[data-nav]");   // 눌린 곳에서 가장 가까운 data-nav 링크
  if (!a) return;                              // 아니면 그냥 둔다
  e.preventDefault();                          // 브라우저 기본 동작(페이지 이동) 취소
  navigate(a.getAttribute("href"));
});
```

여기서 두 가지 기법을 쓴다.

**이벤트 위임** — 링크마다 리스너를 붙이지 않고 `document`에 하나만 붙였다.
클릭은 위로 전파되므로 여기서 다 받을 수 있다. 나중에 JavaScript로 새 링크를
만들어 넣어도 자동으로 동작한다.

**`closest()`** — 링크 안의 `<span>`을 눌렀을 때도 그 부모 `<a>`를 찾아준다.

## 4. 주소 바꾸기와 화면 그리기

```js
// public/js/router.js
function navigate(path){
  if (path !== location.pathname + location.search){
    history.pushState(null, "", path);   // 주소창만 바꾼다 (페이지 이동 없음)
  }
  renderRoute();                          // 화면을 다시 그린다
}
```

`history.pushState`가 핵심이다. **페이지를 다시 받아오지 않고 주소만 바꾼다.**
그리고 방문 이력에 쌓이므로 뒤로가기가 동작한다.

```js
function renderRoute(){
  const route = resolveRoute();     // 현재 주소 → "home" / "forecast" / ...
  updateChrome(route);              // 제목, 탭 활성화 표시 갱신
  if (route === "forecast") renderForecastPage();
  else if (route === "reports") renderReportsPage();
  else renderHomePage();
}
```

## 5. 뒤로가기 처리

`pushState`로 주소를 바꿨으면, 뒤로가기 때 화면도 되돌려야 한다.

```js
window.addEventListener("popstate", () => {
  renderRoute();
});
```

`popstate`는 사용자가 뒤로/앞으로 갈 때 발생한다. 여기서 화면을 다시 그리지
않으면 **주소는 바뀌는데 화면은 그대로**인 상태가 된다.

> 이 저장소는 여기에 한 가지를 더 얹었다. 모바일에서 챗봇이 열려 있을 때
> 뒤로가기를 누르면 앱을 떠나버리는 게 아니라 **챗봇만 닫히게** 했다.
> `public/js/chat.js`의 `chatConsumePopState()`가 그 판단을 한다.

## 6. 서버 설정이 반드시 필요한 이유

여기까지 하면 앱 안에서 이동은 잘 된다. 그런데 **주소창에 `/forecast`를 직접
치거나, 그 화면에서 새로고침하면 404가 난다.**

서버 입장에서는 `/forecast`라는 파일이 없기 때문이다.

해결은 서버 설정 한 줄이다.

```jsonc
// wrangler.jsonc
"assets": {
  "not_found_handling": "single-page-application"
}
```

"없는 주소로 오면 `index.html`을 줘라"는 뜻이다. 그러면 브라우저가 `index.html`을
받고, 그 안의 라우터가 주소를 보고 알맞은 화면을 그린다.

**SPA를 만들 때 가장 흔히 빠뜨리는 설정이다.** 개발 중에는 앱 안에서만 이동하니
모르고 지나가고, 배포 후 사용자가 링크를 공유했을 때 404로 드러난다.

## 7. 화면을 그리는 방식

이 저장소는 **문자열로 HTML을 만들어 `innerHTML`에 넣는다.**

```js
// public/js/home.js
app.innerHTML =
  '<section class="card">' +
    '<h2>전국 파도 현황</h2>' +
    '<div id="home-map">불러오는 중…</div>' +
  '</section>';
```

장점은 의존성이 없고 단순하다는 것. 단점은 따옴표 관리가 번거롭고, 값이 사용자
입력이면 **반드시 이스케이프해야** 한다는 것.

```js
// public/js/util.js — 사용자 입력을 화면에 넣기 전 반드시 통과시킨다
const esc = s => String(s).replace(/[&<>"]/g,
  c => ({ "&":"&amp;", "<":"&lt;", ">":"&gt;", '"':"&quot;" }[c]));
```

→ 왜 필요한지는 [05번 문서의 XSS](./05-데이터-저장하기-D1.md#사용자-입력-다루기-xss)

## 8. 느린 응답이 화면을 덮어쓰는 문제

화면 A를 그리려고 데이터를 기다리는 중에 사용자가 화면 B로 넘어가면, 나중에
도착한 A의 데이터가 B 화면을 덮어쓴다.

이 저장소는 **요청 토큰**으로 막는다.

```js
// public/js/state.js
let reqId = 0;
function nextReqId(){ return ++reqId; }
function isStale(token){ return token !== reqId; }
```

```js
// 각 화면 렌더 함수에서
async function renderHomePage(){
  const my = nextReqId();              // 내 순번을 받아둔다
  const data = await loadSomething();  // 기다리는 동안 다른 화면으로 갔을 수 있다
  if (isStale(my)) return;             // 내 순번이 최신이 아니면 그리지 않고 나간다
  app.innerHTML = ...;
}
```

`await`가 있는 모든 렌더 함수에 이 패턴이 필요하다. **"기다린 뒤에는 아직
유효한지 확인한다"**는 규칙으로 기억하면 된다.

## 9. 직접 해보기

`/about` 화면을 추가해 보자. 손댈 곳이 네 군데다.

**1) `public/index.html`** — 탭 추가
```html
<a href="/about" class="tab" data-nav data-route="about">소개</a>
```

**2) `public/js/router.js`** — 제목 추가
```js
const TITLE_OF = {
  home: "...", forecast: "...", reports: "...", sessions: "...",
  about: "내 웹앱 — 소개",
};
```

**3) `public/js/router.js`** — 주소 인식과 렌더 분기
```js
function resolveRoute(){
  const path = location.pathname;
  // ... 기존 조건들 ...
  if (path === "/about") return "about";
  history.replaceState(null, "", "/");
  return "home";
}

function renderRoute(){
  // ... 기존 분기들 ...
  else if (route === "about") renderAboutPage();
}
```

**4) 화면 함수** — 새 모듈로 만들거나 간단히 `router.js` 안에
```js
function renderAboutPage(){
  app.innerHTML = '<div class="card"><h2>소개</h2><p>내가 만든 앱입니다.</p></div>';
}
```

확인 순서: `npm run dev` → 탭 클릭 → **주소창에 직접 `/about` 입력** →
**새로고침** → **뒤로가기**. 네 가지가 다 되면 완성이다.

---

## 자주 겪는 문제

**탭을 눌렀는데 아무 일도 안 일어난다**
`data-nav` 속성을 빠뜨렸다. 라우터는 `a[data-nav]`만 가로챈다.

**탭 활성화 표시가 안 바뀐다**
`data-route` 값이 `resolveRoute()`가 돌려주는 문자열과 정확히 같아야 한다.

**주소를 직접 치면 404**
`not_found_handling: "single-page-application"` 설정을 확인한다.

**화면이 두 번 그려지거나 이전 화면이 남는다**
`app.innerHTML = ...`로 통째로 교체하는지 확인한다. `+=`를 쓰면 덧붙는다.

**`Cannot read properties of null (reading 'innerHTML')`**
요소를 찾기 전에 접근했다. `<script type="module">`은 자동으로 지연 실행되므로
보통 문제가 없지만, HTML에 그 `id`가 실제로 있는지 확인한다.
