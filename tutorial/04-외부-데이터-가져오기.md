# 04. 외부 데이터 가져오기

목표: 외부 API를 붙이는 두 가지 방식(브라우저 직접 / 서버 경유)을 **언제 어느
쪽을 쓰는지** 판단할 수 있게 되는 것. 그리고 인증키를 안전하게 다루는 법.

이 문서의 내용이 이 프로젝트에서 **가장 많은 시행착오가 있었던 부분**이다.

---

## 1. 판단 기준: 브라우저에서 직접 vs 서버 경유

```
외부 API를 붙여야 한다
        │
        ├─ 인증키가 필요한가? ──── 예 ──▶ 서버 경유 (무조건)
        │                                 키를 브라우저에 두면 공개된다
        └─ 아니오
                │
                ├─ CORS를 허용하는가? ── 아니오 ──▶ 서버 경유
                │                                   브라우저가 차단한다
                └─ 예
                        │
                        ├─ 호출량이 방문자 수에 비례해도 괜찮은가?
                        │        아니오 ──▶ 서버에서 모아두기 (06번 문서)
                        └─ 예 ──▶ 브라우저에서 직접 (가장 단순, 서버 비용 0)
```

이 저장소는 두 가지를 다 쓴다.

| API | 방식 | 이유 |
|---|---|---|
| Open-Meteo (파도 예보) | **브라우저 직접** | 인증키 없음, CORS 허용, 방문자별 호출이 괜찮은 규모 |
| 정부 기관 API (특보) | **서버 경유** | 인증키 필요 + CORS 미허용 |
| 전국 지도용 13개 지점 | **서버가 모아둠** | 방문자마다 부르면 무료 한도가 녹는다 → [06번](./06-정기작업-Cron.md) |

## 2. CORS란 무엇이고 왜 막히나

브라우저는 "지금 보고 있는 사이트가 **다른 도메인**에 요청해도 되는지"를
검사한다. 상대 서버가 `Access-Control-Allow-Origin` 헤더로 허용해야 통과한다.

```
내 사이트(myapp.workers.dev) → api.example.com 요청
   상대가 허용 헤더를 주면      → 성공
   안 주면                     → 브라우저가 차단 (콘솔에 CORS 에러)
```

중요한 점 두 가지.

**1) 막는 건 브라우저다.** 서버끼리는 CORS가 적용되지 않는다. 그래서 내 서버가
대신 부르면 우회된다 — 우회가 목적이 아니라, 원래 CORS는 브라우저 사용자를
보호하는 규칙이라 서버 간 통신에는 해당이 없는 것이다.

**2) CORS 에러는 내 코드로 고칠 수 없다.** 상대 서버 설정이라서, 방법은 서버
경유뿐이다.

## 3. 브라우저에서 직접 부르기

```js
// public/js/api.js 의 패턴
async function getJSON(url){
  const res = await fetch(url);
  if (!res.ok) throw new Error("HTTP " + res.status);
  return res.json();
}
```

**`res.ok` 확인을 빠뜨리지 않는다.** `fetch`는 404·500에도 예외를 던지지 않는다.
확인 없이 `res.json()`을 부르면 에러 페이지 HTML을 JSON으로 해석하려다
엉뚱한 에러가 난다.

### 실패해도 화면이 죽지 않게

```js
// 이 저장소는 부가 기능의 실패를 조용히 흡수한다
let advisoryPromise = null;
function loadAdvisory(){
  if (!advisoryPromise){
    advisoryPromise = fetch("/api/advisory")
      .then(r => r.json())
      .catch(() => ({ ready: false, reason: "fetch_failed" }));   // 실패도 정상 값으로
  }
  return advisoryPromise;
}
```

두 가지 기법이 들어 있다.

**실패를 값으로 바꾸기** — 예외를 던지지 않고 `{ ready: false }`를 돌려준다.
그러면 호출부가 `try/catch` 없이 `if (!data.ready)`로 처리할 수 있고, **부가
기능이 죽어도 주요 화면은 뜬다.**

**한 번만 부르기** — `advisoryPromise`에 담아두고 재사용한다. 화면을 여러 번
그려도 네트워크 요청은 한 번이다.

## 4. 서버 경유 (프록시)

`src/worker.js`의 구조.

```js
export default {
  async fetch(request, env, ctx){
    const url = new URL(request.url);
    if (url.pathname === "/api/advisory") return handleAdvisory(request, env, ctx);
    return env.ASSETS.fetch(request);
  },
};

async function handleAdvisory(request, env, ctx){
  if (!env.KMA_SERVICE_KEY){
    // 키가 아직 없으면 에러가 아니라 "준비 안 됨"을 알려준다
    return Response.json({ ready: false, reason: "no_service_key" });
  }
  try {
    const data = await fetchFromExternalAPI(env.KMA_SERVICE_KEY);
    return Response.json({ ready: true, data });
  } catch (err) {
    return Response.json({ ready: false, reason: "upstream_error" }, { status: 502 });
  }
}
```

**설정이 안 됐을 때도 정상 응답을 준다**는 점이 중요하다. 이 저장소는 인증키가
없어도 앱이 돌아간다 — 배너가 "연동 준비 중"으로 뜰 뿐이다. 그래서 키를
등록하는 순간 **코드 수정 없이** 실데이터로 전환됐다.

## 5. 인증키(시크릿) 다루기

### 절대 하지 말 것

```js
const KEY = "abc123...";           // ❌ 브라우저 코드에 넣기 → 누구나 볼 수 있다
```

```jsonc
// wrangler.jsonc
"vars": { "API_KEY": "abc123..." }  // ❌ 이 파일은 git 에 올라간다
```

### 올바른 방법

**운영(배포된 서버)** — Cloudflare에 등록한다. 코드나 저장소에 남지 않는다.

```bash
npx wrangler secret put KMA_SERVICE_KEY
# 프롬프트가 뜨면 값을 붙여넣는다

npx wrangler secret list      # 등록된 키 이름 목록 (값은 안 보인다)
```

**로컬 개발** — `.dev.vars` 파일에 넣고, 이 파일을 `.gitignore`에 넣는다.

```
# .dev.vars  (git 에 올라가지 않는다)
KMA_SERVICE_KEY=실제키값
```

둘 다 코드에서는 똑같이 `env.KMA_SERVICE_KEY`로 읽힌다.

> 팀에 공유할 때는 값이 빈 **`.dev.vars.example`**을 만들어 커밋한다. "이런
> 이름의 키가 필요하다"는 정보만 남기고 값은 각자 채우게 한다.

### 실수로 커밋했다면

**파일을 지우는 것으로 끝나지 않는다.** git 히스토리에 영구히 남는다.
반드시 **그 키를 폐기하고 새로 발급받아야** 한다.

## 6. 이 프로젝트에서 실제로 겪은 세 가지 함정

이 절이 이 문서에서 가장 실용적인 부분이다.

### 함정 1: 이중 인코딩

발급받은 인증키가 이미 URL 인코딩된 형태(`%2B`, `%2F` 같은 문자 포함)였다.
그걸 `URLSearchParams`에 넣으니 **한 번 더** 인코딩돼서 계속 거부당했다.

```js
// ❌ 이미 인코딩된 키를 다시 인코딩한다
const qs = new URLSearchParams({ serviceKey: key });

// ✅ 원문으로 되돌린 뒤 넘기면 정확히 한 번만 인코딩된다
const qs = new URLSearchParams({ serviceKey: decodeURIComponent(key) });
```

**증상**: 인증 실패인데 키는 분명히 맞다. **확인법**: 만들어진 URL을 그대로
찍어보고, `%25`(=`%`가 인코딩된 것)가 보이면 이중 인코딩이다.

### 함정 2: 문서와 실제 응답이 다르다

API 문서를 보고 응답 필드 이름을 가정해 파싱 코드를 다 짰는데, 실제 응답에는
그런 필드가 없었다. 지역명이 올 거라 생각한 자리에 숫자 코드가 왔고, 필요한
정보는 **자유 텍스트 안에** 들어 있었다.

**교훈**: **붙이기 전에 한 번 호출해서 실제 응답을 눈으로 본다.**

```bash
# 이런 임시 스크립트를 만들어 응답을 찍어본다 (확인 후 삭제)
node -e "fetch('https://api.example.com/...?key=...').then(r=>r.text()).then(console.log)"
```

응답 구조를 확인한 다음에 코드를 짠다. 순서를 바꾸면 시행착오가 몇 배가 된다.

### 함정 3: 로컬은 되는데 배포하면 실패

같은 키로 로컬에서는 성공, 배포된 서버에서는 계속 인증 실패였다. 원인은
비밀키를 등록하는 과정에서 **눈에 안 보이는 문자(개행) 하나가 섞여 들어간** 것.
키 길이를 찍어보니 원본보다 1글자 길었다.

```js
// 소비하는 쪽에서 방어했다 — 시크릿 앞뒤 공백은 유효한 값일 수 없다
decodeURIComponent(serviceKey.trim())
```

**교훈**: 로컬과 배포가 다르게 동작하면 **환경 차이(설정값·비밀키)를 먼저**
의심한다. 코드는 같기 때문이다. 확인하려면 값 자체가 아니라 **길이나 해시**를
찍는다(값을 로그에 남기면 그게 유출이다).

## 7. 외부에서 온 데이터를 믿지 않기

### 요약값을 다시 계산한다

GPS 파일에 기기가 계산해 넣은 "평균 속도·총 거리" 필드가 있었는데, 실제
좌표로 계산한 값과 달랐다(고도가 40m→37m로 변하는데 상승/하강이 0으로 찍혀
있었다).

**그래서 원시 좌표만 받고, 거리·시간·평균은 서버가 다시 계산한다.**

```
클라이언트 → 원시 좌표 배열만 전송
서버       → 거리·시간·매칭 결과를 직접 계산해 저장
```

이러면 기기·앱이 무엇이든 같은 로직 하나로 처리되고, 클라이언트가 값을
조작해 보내도 저장되는 건 서버 계산 결과다.

### 구조를 방어적으로 읽는다

```js
// 예상과 다른 구조가 와도 프로그램이 멈추지 않는다
const items = data?.response?.body?.items?.item ?? [];
```

### 문자열도 신뢰하지 않는다

외부에서 온 문자열(특히 AI가 생성한 답변)을 화면에 넣을 때도 이스케이프한다.
→ [05번 문서](./05-데이터-저장하기-D1.md#사용자-입력-다루기-xss)

## 8. 직접 해보기

무인증 공개 API를 브라우저에서 직접 불러 화면에 표시해 보자.

```js
// public/js/api.js 에 추가
async function loadJoke(){
  const res = await fetch("https://api.github.com/zen");   // 인증 없이 되는 API
  if (!res.ok) throw new Error("HTTP " + res.status);
  return res.text();
}
export { loadJoke };
```

```js
// 화면 함수에서
import { loadJoke } from "./api.js";
import { esc } from "./util.js";

async function renderAboutPage(){
  app.innerHTML = '<div class="card">불러오는 중…</div>';
  try {
    const text = await loadJoke();
    app.innerHTML = '<div class="card"><p>' + esc(text) + '</p></div>';
  } catch (e) {
    app.innerHTML = '<div class="card">불러오지 못했습니다.</div>';
  }
}
```

**세 가지를 반드시 넣는다**: 로딩 표시 / `res.ok` 확인 / 실패 시 대체 화면.

## 자주 겪는 문제

**콘솔에 `blocked by CORS policy`**
상대 서버가 허용하지 않는다. 서버 경유로 바꾼다. 내 코드로는 못 고친다.

**`env.MY_KEY`가 `undefined`**
로컬이면 `.dev.vars`에 있는지, 배포면 `wrangler secret list`에 있는지 확인한다.
`.dev.vars`를 고쳤으면 `wrangler dev`를 재시작해야 한다.

**`Unexpected token '<' ... is not valid JSON`**
JSON을 기대한 곳에 HTML이 왔다. 대개 404 페이지다. `res.ok`를 확인하고,
요청 URL이 맞는지 본다.

**응답이 계속 옛날 값**
캐시다. 이 저장소는 `fetch(url, { cache: "no-store" })`를 쓰거나 서버에서
`cache-control: no-store`를 준다.
